# 打卡与审核 SOP（操作手册）

> 最后更新：2026-08-17
> 依据：`CLAUDE.md` 核心工作流 + `用户反馈与偏好.md`「审核范围（用户强调！）」
> 配套工具：`打卡台.html`（网页版 App）

---

## 一、两级模式（必读）

| 级别 | 触发词 | 做什么 | 不做什么 |
|------|--------|--------|----------|
| ? 快速打卡 | 「打卡」 | 更新 checkbox、更新 `当前状态.md`、一句话鼓励 | 不批改答案、不审笔记、不入错题本 |
| ? 深度审核 | 「打卡+审核」「交作业」或**附上答案/笔记** | 批改答案 + 审笔记 + 入错题本 + 更新状态 | — |

> ? 建议：日常用「打卡」快速记录；每 2-3 天或周末用「打卡+审核」做一次深度回顾（token 节省 ~80%）。

## 零填写打卡（已上线）

**1. 一键打卡**
进入任意板块 → 顶部「今日状态」区点 **? 一键打卡**，自动生成一条当日记录：
- 任务文本：优先读取本周计划里该板块今日任务（见下「计划缓存」）；读不到则用板块目标兜底。
- 时长：按板块默认值（跑步 30 / 嵌入式 45 / AI 40 / 软考 35 分）。
- 同时自动写入一条「快速审核」自评，闭环不中断。
- 想补细节（真实时长/疼痛/备注）再点「详细填写」即可。

**2. 本周路径自动探测（无需手动设置）**
打开「每日审核」→ 工作台默认按**当前日期所在周（周一~周日）**自动推断：
`每日计划/2026年MM月/YYYYMMDD-YYYYMMDD周计划.md` + 同名 `…习题.md`。
所有「计划/习题/错题本」链接自动就绪。如需改手动路径，点「重设」即可。

**3. 计划缓存（让一键打卡带上真实任务，可选）**
对话 agent 解析周计划后，会把四板块今日任务以 JSON 存好；在「每日审核→重设」弹窗的「今日计划」框粘贴：
```json
{"running-rehab":"弹力带力量·30'","embedded-workflow":"EAS深化","ai-trainer":"MCP实战","senior-architect":"软考月考"}
```
之后「一键打卡」的 topic 即显示具体任务，而非兜底目标。

## 一·五、错误收集（打卡后自动批改归集）

一键打卡完成 → 审核页出现 **? 错误收集（批改今日习题）** 按钮：

1. 点按钮 → 自动按日期筛出**今日应做习题**（来自本周习题库缓存）。
2. 勾选你的答案 → 点「批改收集」→ 对照正确答案自动批改。
3. **错题自动归集**：按板块前缀生成 `EW/AI/SE/RK-YYYYMMDD-序号` 条目，含 `> ?? 你的 / > ? 正确 / > ? 解析`。
4. 点「复制错题 Markdown」→ 粘贴到对应 `错题本.md` 即完成同步（Web 端不直接写文件，由你或对话 agent 落盘）。
5. 题目缓存每周由对话 agent 解析习题库后更新（结构见 `打卡台.html` 内 `wb_pa_quiz_<周标签>`）。

> 这实现了 CLAUDE.md 的「批改答案 + 入错题本」闭环的 Web 侧采集，深度笔记审核仍由对话 agent 执行。

## 二、打卡步骤（快速）

1. 打开 `打卡台.html` → 进入对应板块（跑步康复/嵌入式/AI学习/软考）。
2. 填写时长、内容/主题、疼痛标记 → 点「打卡」。
3. 打卡后首页「今日待审核」提醒出现 → 进入「每日审核」做①快速审核自评。

---

## 三、深度审核步骤（对接真实资料体系）

### 1. 准备本周资料路径
打开 `打卡台.html` → 「每日审核」→「设置本周资料路径」，填入：
- **周计划**：`每日计划/2026年MM月/YYYYMMDD-YYYYMMDD周计划.md`
- **习题**：`每日计划/2026年MM月/YYYYMMDD-YYYYMMDD习题.md`

打开「每日审核」时**已按当前日期所在周自动探测**上述路径，四板块的「计划/习题/错题本」链接自动就绪；如需改手动路径，点「重设」即可。

### 2. 在对话中驱动 AI 深度审核
发送形如：
```
打卡+审核
康复：今日力量+慢跑40' 0疼痛
嵌入式：EAS深化 25min（见笔记 …/03-功耗优化.md）
AI：多Agent架构设计，答案Q5=消息队列解耦
软考：月考卷Q1-Q3 我的答案…
附笔记：AI学习/进阶实战/02-Agent协作.md
```
AI 会：
1. 读 `周计划.md` + `习题.md`（含答案解析）。
2. 更新周计划 checkbox（`- [ ]`→`- [x]`）。
3. **批改答案**：对照正确答案，错误用：
   ```
   > ?? 你的答案：XXX
   > ? 正确答案：YYY
   > ? 解析：...
   ```
4. **审笔记**：检查 `.md` 概念错误/理解偏差，同样格式标注，归入错题本。
5. 把错题追加到对应错题本（格式见下）。
6. 更新 `用户反馈与偏好.md` 的今日心得、`当前状态.md`。

### 3. 回填 Web 工作台
AI 批改完成后，回到 `打卡台.html` →「每日审核」→「深度审核工作台」，
对已完成批改的板块点「深度审」按钮（变 ?已审），形成可视闭环。

## 四、错题本落点（编号前缀）

| 板块 | 错题本路径 | 前缀 |
|------|-----------|------|
| ? 跑步康复 | `康复训练/错题本.md` | `RK-YYYYMMDD-序号` |
| ? 嵌入式 | `嵌入式工作流/错题本.md` | `EW-YYYYMMDD-序号` |
| ? AI学习 | `AI学习/错题本.md` | `AI-YYYYMMDD-序号` |
| ? 软考 | `软考备考/错题本.md` | `SE-YYYYMMDD-序号` |

### 错题追加格式
```markdown
### RK-20260817-01

**日期**：2026-08-17
**来源**：每日计划打卡 / 笔记审核 — `路径/文件.md`
**原题**：...
> ?? 你的答案/表述：XXX
> ? 正确答案：YYY
> ? 解析：...
```

## 五、审核范围红线（用户强调）

- ?? 不仅要审**昨日打卡答案**，还要审**新写的学习笔记 `.md`**。
- ?? 笔记审核标准：概念错误、理解偏差、表述不当；发现问题用 `> ?? / > ? / > ?` 标注并归入错题本。
- ?? 弹力带动作必须标注磅数（20/30/40磅），不得笼统写「弹力带」。

## 五·五、云同步（小程序 ? 网页 同一份数据）

> 打卡数据现已支持**小程序与网页共享同一云数据库**（按微信 unionid 对齐）。一次打卡，两端可见。

**开启云同步（一次性，需云控制台操作）**
1. 微信开放平台：将小程序与网页应用绑定到**同一开放平台账号**（否则 unionid 不同，两端数据不互通）。
2. 云开发控制台：把 `打卡台.html` 部署域名的 host 加入**Web 安全域名**。
3. 云开发控制台：将 `checkins` 集合权限设为「**所有用户可读，仅创建者可读写**」（读不按 `_openid` 隔离才能跨端互通；写仍仅创建者，互不覆盖；详见 CODEBUDDY.md）。并新建复合索引 `(unionid, date)` 与 `(unionid, recId)`，否则查询会报「need index」。`fitness`/`wrongbooks` 保持「仅创建者可读写」不变。
4. 浏览器通过 **https 域名**（非 file://）打开 `打卡台.html` → 点「? 云同步登录」→ 跳转微信授权 → 返回即完成同步。

**日常使用**
- 联网且已登录：打卡实时写入云端，小程序与其他设备立即可见。
- 断网 / 未登录：仍在本地记录，恢复联网后自动补齐（写队列按 recId 幂等合并）。
- 本地 `localStorage` 仍是离线缓存与兜底；首次加载先读本地再合并云端。
- 审核、错题本等仍按原 SOP 在本地 + 对话 agent 流程进行（本次共享聚焦 checkins）。

## 六、数据备份

`打卡台.html` 的「导出/导入」已同时包含打卡与审核记录（JSON `{records, audits}`）。
建议每周导出一次，防止本地存储清空调丢数据。云同步开启后，云端为唯一数据源，导出文件可作为额外离线备份。
